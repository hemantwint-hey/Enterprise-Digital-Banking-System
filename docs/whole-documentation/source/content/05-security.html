2.1 Token format

Header : { "alg": "HS256" }
Payload: { "sub": "hemant@example.com", "iat": 1760366400, "exp": 1760452800 }
Signature: HMACSHA256(base64url(header) + "." + base64url(payload), JWT_SECRET)
  • JWT_SECRET must be at least 256 bits (32+ random bytes) — Keys.hmacShaKeyFor rejects shorter keys.
  • Expiry: jwt.expiration ms (default 86 400 000 = 24 h). Target: 15 min access token + 7 day refresh token PLANNED.
  • The token carries no role claim; the role is re-read from the database on every request, so a role change takes effect immediately.
  • Tokens cannot be revoked before expiry GAP. Planned: refresh-token table + deny-list of jti in Redis on logout.
  • UserStatus (BLOCKED / SUSPENDED) is not checked at login or in CustomUserDetails.isEnabled() GAP.

6.1 Rules

  • Never put real values in application*.properties, docker-compose.yml or the README; reference ${VAR} only.
  • Local: IntelliJ run-configuration env vars or a git-ignored .env file read by Docker Compose.
  • AWS: Elastic Beanstalk environment properties, or AWS Secrets Manager / SSM Parameter Store for rotation.
  • CI: GitHub Actions repository secrets.
  • Generate the JWT secret with openssl rand -base64 48. Rotating it invalidates all issued tokens (users log in again).
  • Verify nothing leaked: git log --all -- .env must be empty. Add .env to .gitignore PLANNED.
  • Gmail SMTP requires an App Password, never the account password.

7.2 Rules

  • Written in the same DB transaction as the change: if the business operation rolls back, so does its audit row (no phantom audit entries).
  • Never store passwords, tokens, full Aadhaar/PAN or card numbers in old_value / new_value.
  • Audit rows are append-only: no update/delete endpoint exists, and the DB user for the app should eventually have no UPDATE/DELETE grant on audit_logs.
  • Read access: ADMIN and AUDITOR only (planned). Retention ≥ 8 years.
  • Failed-login audits survive the exception that follows them because UserServiceImpl is not transactional — each AuditService.log call commits on its own. Keep it that way (or use REQUIRES_NEW) if @Transactional is ever added to the login method.
