2. Authentication

2.1 Flow

  1. POST /auth/register once to create a user (role CUSTOMER).
  2. POST /auth/login with e-mail + password → response contains token.
  3. Send Authorization: Bearer <token> on every /api/v1/** call. Tokens expire after jwt.expiration (default 24 h); log in again afterwards.
  4. Missing / invalid / expired token → 401 with the standard error body.

POST /auth/register   public

FieldTypeRules
fullNamestringrequired, 3–100
usernamestringrequired, 3–50
emailstringrequired, e-mail format, unique
phoneNumberstringrequired, ^[6-9]\d{9}$
passwordstringrequired, ≥ 8
confirmPasswordstringrequired, must equal password
// Request
{ "fullName": "Hemant Mahto", "username": "hemant", "email": "hemant@example.com",
  "phoneNumber": "9876543210", "password": "Secret@123", "confirmPassword": "Secret@123" }
// 201 Created
{ "success": true, "message": "User Registered Successfully" }

Errors: 400 validation · 409 “Email already exists” · 401 “Password do not match”

Errors: 400 validation · 404 “Invalid email id” · 401 “Password didnt match”

  "address": "12 MG Road", "city": "Ranchi", "state": "Jharkhand", "country": "India",
  "postalCode": "834001", "email": "hemant@example.com" }
// 201 Created  (CustomerResponse)
{ "customerId": 1, "firstName": "Hemant", "lastName": "Mahto", "dateOfBirth": "2000-05-14",
  "phoneNumber": "9876543210", "address": "12 MG Road", "city": "Ranchi", "state": "Jharkhand",
  "country": "India", "postalCode": "834001", "kycStatus": "PENDING",
  "createdAt": "2026-10-13T20:10:11.402" }

Errors: 404 user not found for e-mail · 409 profile already exists / phone already used

GET /api/v1/customers/{customerId} · GET /api/v1/customers/user/{userId}

Return CustomerResponse (shape above). 404 when not found.

GET /api/v1/customers — list (CustomerSummaryResponse[])

[ { "customerId": 1, "firstName": "Hemant", "lastName": "Mahto", "phoneNumber": "9876543210",
    "city": "Ranchi", "kycStatus": "VERIFIED" } ]

PUT /api/v1/customers/{customerId} — full update

Body: same fields as create except email; names 2–50. 409 if the phone belongs to another customer.

PATCH /api/v1/customers/{customerId}/kyc — complete KYC

// Request
{ "panNumber": "ABCDE1234F", "aadhaarNumber": "123412341234" }
// 200 OK -> CustomerResponse with "kycStatus": "VERIFIED"

Rules: PAN ^[A-Z]{5}[0-9]{4}[A-Z]$, Aadhaar ^\d{12}$; 409 if linked to another customer. Side effect: users.kyc_verified = true.

DELETE /api/v1/customers/{customerId} → 204 No Content

Resets the user’s kycVerified. Fails (500, FK violation) if the customer still has accounts/loans GAP.

7. Loans and EMIs

POST /api/v1/loans

// Request
{ "customerId": 1, "disbursementAccountId": 1, "loanType": "PERSONAL",
  "principalAmount": 100000.00, "interestRate": 12.00, "tenureMonths": 12 }
// 201 Created (LoanResponse)
{ "id": 1, "customerId": 1, "disbursementAccountNumber": "100483920175", "loanType": "PERSONAL",
  "principalAmount": 100000.00, "interestRate": 12.00, "tenureMonths": 12, "emiAmount": 8884.88,
  "status": "PENDING", "createdAt": "2026-10-13T20:25:00", "approvedAt": null, "closedAt": null }

Rules: principal ≥ 1000, interest ≥ 0.01, tenure 1–360. EMI = P·r·(1+r)n/((1+r)n−1), r = rate/1200.

GET /api/v1/loans/{loanId} · GET /api/v1/loans/customer/{customerId}

PATCH /api/v1/loans/{loanId}/approve — credits principal to the disbursement account, status ACTIVE, creates tenureMonths EMIs.

PATCH /api/v1/loans/{loanId}/reject — status REJECTED.

Both: 400 “Loan is ACTIVE and cannot be approved/rejected” unless PENDING. Intended for MANAGER role PLANNED.

GET /api/v1/emis/loan/{loanId} — schedule ordered by installment

[ { "id": 1, "loanId": 1, "installmentNumber": 1, "dueDate": "2026-11-13", "amount": 8884.88,
    "status": "PENDING", "paidAt": null }, ... ]

PATCH /api/v1/emis/{emiId}/pay → EmiResponse with "status": "PAID". 400 “EMI is already paid”. Paying the last EMI closes the loan.

11. Quick-start cURL Script

BASE=http://localhost:8080
curl -s -X POST $BASE/auth/register -H "Content-Type: application/json" -d '{"fullName":"Hemant Mahto",
  "username":"hemant","email":"hemant@example.com","phoneNumber":"9876543210",
  "password":"Secret@123","confirmPassword":"Secret@123"}'
TOKEN=$(curl -s -X POST $BASE/auth/login -H "Content-Type: application/json" \
  -d '{"email":"hemant@example.com","password":"Secret@123"}' | jq -r .token)
H="Authorization: Bearer $TOKEN"
curl -s -X POST $BASE/api/v1/customers -H "$H" -H "Content-Type: application/json" -d '{"firstName":"Hemant",
  "lastName":"Mahto","dateOfBirth":"2000-05-14","phoneNumber":"9876543210","address":"12 MG Road",
  "city":"Ranchi","state":"Jharkhand","country":"India","postalCode":"834001","email":"hemant@example.com"}'
curl -s -X POST $BASE/api/v1/accounts -H "$H" -H "Content-Type: application/json" \
  -d '{"customerId":1,"accountType":"SAVINGS","branch":"Main","openingBalance":5000}'
curl -s -X POST $BASE/api/v1/accounts -H "$H" -H "Content-Type: application/json" \
  -d '{"customerId":1,"accountType":"CURRENT","branch":"Main","openingBalance":0}'
curl -s -X POST $BASE/api/v1/transactions/transfer -H "$H" -H "Content-Type: application/json" \
  -d '{"sourceAccountId":1,"destinationAccountId":2,"amount":1000,"remarks":"test"}'
curl -s $BASE/api/v1/ledger/account/1 -H "$H"
