1. Project Overview

Enterprise Digital Banking System is a Spring Boot backend that simulates a retail bank: JWT-secured users, customers with KYC, accounts, deposits/withdrawals/transfers on a double-entry ledger, beneficiaries, loans with EMI schedules and a complete audit trail. A separate notification-service consumes Kafka events and notifies customers.

BR-03KYCCompleting KYC sets the customer VERIFIED and the user’s kycVerified flag; deleting the customer resets it.CustomerServiceImpl

BR-06AccountsA CLOSED account cannot be updated, frozen or closed again. Freezing a FROZEN account is rejected.AccountServiceImpl
BR-07AccountsAn account can be closed only when its balance is exactly zero.AccountServiceImpl
BR-08TransactionsMinimum amount is 1.00; remarks ≤ 255 chars.DTO validation
BR-09TransactionsOnly ACTIVE accounts can send or receive money.TransactionServiceImpl
BR-10TransactionsWithdrawals and transfers cannot exceed the available balance (no overdraft).TransactionServiceImpl
BR-11TransfersExactly one of destination account / beneficiary; source ≠ destination.TransactionServiceImpl
BR-12TransfersA beneficiary used for a transfer must be ACTIVE and belong to the source account’s customer.TransactionServiceImpl
BR-13LedgerDeposit = 1 CREDIT; withdrawal = 1 DEBIT; transfer = 1 DEBIT + 1 CREDIT of equal amount. Each line stores the balance after posting.LedgerServiceImpl
BR-14TransactionsEvery transaction has a unique reference “TXN” + 13 digits.TransactionServiceImpl
BR-15BeneficiariesThe same account cannot be added twice by one customer. New beneficiaries are PENDING and must be activated before use.BeneficiaryServiceImpl
BR-16LoansPrincipal ≥ 1 000; interest rate ≥ 0.01 % p.a.; tenure 1–360 months.DTO validation
BR-17LoansEMI = P·r·(1+r)n / ((1+r)n−1), r = annual rate / 12 / 100, rounded HALF_UP to 2 decimals.LoanServiceImpl
BR-18LoansOnly PENDING loans can be approved or rejected. Approval credits the principal to the disbursement account and creates one EMI per month, due monthly from the approval date.LoanServiceImpl, EmiServiceImpl
BR-19EMIsAn EMI can be paid once. When no unpaid EMI remains, the loan becomes CLOSED.EmiServiceImpl
BR-20NotificationsTransfers and beneficiary activations emit events; each event is notified at most once (idempotency key = eventId).Producers, notification-service
BR-21AuditAudit entries never contain passwords and are never modified or deleted.AuditServiceImpl

4.3 Adding a new feature module (checklist)

  1. Create package <feature>/ with entity, repository, dto/request, dto/response, mapper, service + service/impl, controller.
  2. Entity: @Entity @Table(name = "plural_snake"), Lombok builder, @ManyToOne(fetch = LAZY) to parents, @Enumerated(STRING), money precision = 18, scale = 2, @PrePersist for createdAt and default status.
  3. Request DTOs with Bean Validation and clear messages; response DTOs never expose entities or sensitive fields.
  4. Service interface + @Service @RequiredArgsConstructor @Transactional impl; readOnly = true on queries; throw ResourceNotFoundException / BadRequestException.
  5. Call auditService.log(...) on every state change.
  6. Never inject another module’s service if it already depends on yours — use its repository (ADR-005).
  7. Controller under /api/v1/<plural>; 201 for create, 204 for delete.
  8. Add a Flyway migration (once Flyway is in), unit tests for every branch, and update documents 02 and 04.
