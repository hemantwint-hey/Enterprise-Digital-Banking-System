1. Core Concepts: How Bean Validation Works in Spring Boot 4

In an enterprise banking API, every byte crossing the HTTP boundary is untrusted input. Relying only on database CHECK constraints (Day 70) or manual if/else checks in service methods wastes database connections, thread-pool slots, and Kafka I/O when malformed inputs can be rejected in microseconds at the Web/Controller boundary.

HTTP Request (JSON / Path / Query) │ ├─► Jackson 3 Deserializer ──(bad JSON / invalid Enum?)──► HttpMessageNotReadableException ──► 400 Bad Request │ ├─► @Valid on @RequestBody ──(field/class rule fails?)──► MethodArgumentNotValidException ─► 400 + fieldErrors Map │ ├─► @Validated on @RestController (@PathVariable / @RequestParam) │ └─(Spring 7 MethodValidation)───────────────────► HandlerMethodValidationException ─► 400 Bad Request │ └─► Validated DTO enters @Service ──► Clean Business Logic + ACID Ledger

@Valid (Jakarta Standard)

  • Triggers validation on @RequestBody and @ModelAttribute objects.
  • Cascades validation recursively into nested objects/lists when placed on fields.
  • Throws MethodArgumentNotValidException in Spring MVC.
  • Does NOT support validation groups or method-level primitives on its own.

@Validated (Spring Framework)

  • Placed on the @RestController class to enable proxy/method validation for @PathVariable and @RequestParam (e.g., @Positive Long accountId).
  • Supports Validation Groups (e.g., OnCreate.class vs OnUpdate.class).
  • In Spring Framework 6.1+ / 7.0 (Boot 4.1), triggers HandlerMethodValidationException natively inside RequestMappingHandlerAdapter.

Essential Constraint Distinctions (Interview Favorite)

Annotation Rejects null? Rejects ""? Rejects " "? Banking Usage Rule
@NotNull YES NO NO Enums (AccountType), IDs (Long), BigDecimal, LocalDate.
@NotEmpty YES YES NO Non-empty collections / arrays (List<Long>).
@NotBlank YES YES YES Strings: branch, email, reason, panNumber.
@Digits(integer=16, fraction=2) No (pair w/ @NotNull) N/A N/A Matches MySQL DECIMAL(18,2); stops sub-paise inputs like 100.1234!

import jakarta.validation.ConstraintViolationException;
import org.springframework.http.converter.HttpMessageNotReadableException;
import org.springframework.web.method.annotation.HandlerMethodValidationException;
import java.util.LinkedHashMap;
import java.util.Map;

// 1. @RequestBody DTO field & class-level constraint violations (400)
@ExceptionHandler(MethodArgumentNotValidException.class)
public ResponseEntity<ErrorResponse> handleValidationException(
        MethodArgumentNotValidException ex, HttpServletRequest request) {

    Map<String, String> fieldErrors = new LinkedHashMap<>();
    ex.getBindingResult().getFieldErrors().forEach(fe ->
            fieldErrors.putIfAbsent(fe.getField(), fe.getDefaultMessage()));
    ex.getBindingResult().getGlobalErrors().forEach(ge ->
            fieldErrors.putIfAbsent(ge.getObjectName(), ge.getDefaultMessage()));

    String summary = fieldErrors.entrySet().stream()
            .map(e -> e.getKey() + ": " + e.getValue())
            .collect(Collectors.joining(", "));

    return new ResponseEntity<>(
            new ErrorResponse(LocalDateTime.now(), HttpStatus.BAD_REQUEST.value(),
                    summary, request.getRequestURI(), fieldErrors),
            HttpStatus.BAD_REQUEST);
}

// 2. Spring Boot 4 / Framework 7 @PathVariable & @RequestParam validation errors (400)
@ExceptionHandler(HandlerMethodValidationException.class)
public ResponseEntity<ErrorResponse> handleMethodValidation(
        HandlerMethodValidationException ex, HttpServletRequest request) {

    Map<String, String> fieldErrors = new LinkedHashMap<>();
    ex.getParameterValidationResults().forEach(result -> {
        String param = result.getMethodParameter().getParameterName();
        result.getResolvableErrors().forEach(err ->
                fieldErrors.putIfAbsent(param != null ? param : "parameter", err.getDefaultMessage()));
    });

    return new ResponseEntity<>(
            new ErrorResponse(LocalDateTime.now(), HttpStatus.BAD_REQUEST.value(),
                    "Validation failed for request parameter(s)", request.getRequestURI(), fieldErrors),
            HttpStatus.BAD_REQUEST);
}

// 3. Direct Bean Validation / Service-layer ConstraintViolationException (400)
@ExceptionHandler(ConstraintViolationException.class)
public ResponseEntity<ErrorResponse> handleConstraintViolation(
        ConstraintViolationException ex, HttpServletRequest request) {

    Map<String, String> fieldErrors = new LinkedHashMap<>();
    ex.getConstraintViolations().forEach(v ->
            fieldErrors.putIfAbsent(v.getPropertyPath().toString(), v.getMessage()));

    return new ResponseEntity<>(
            new ErrorResponse(LocalDateTime.now(), HttpStatus.BAD_REQUEST.value(),
                    "Constraint violation", request.getRequestURI(), fieldErrors),
            HttpStatus.BAD_REQUEST);
}

// 4. Malformed JSON, wrong date format, or invalid Enum constant (e.g. accountType="CRYPTO")
@ExceptionHandler(HttpMessageNotReadableException.class)
public ResponseEntity<ErrorResponse> handleUnreadableMessage(
        HttpMessageNotReadableException ex, HttpServletRequest request) {
    return buildResponse(HttpStatus.BAD_REQUEST,
            "Malformed JSON payload or invalid field value/enum format", request);
}
Why HttpMessageNotReadableException matters: Previously, sending {"accountType": "INVALID"} threw HttpMessageNotReadableException, which fell through to handleGenericException and returned an alarming 500 Internal Server Error! Catching it returns a clean 400 Bad Request.

4. Planned Code: Custom Banking Constraint Annotations

Custom Jakarta Bean Validation annotations eliminate repetitive validation code across controllers and DTOs while expressing real domain rules declaratively.

src/main/java/.../common/validation/MinimumAge.java & MinimumAgeValidator.java NEW 
package org.example.enterprisedigitalbankingsystem.common.validation;

import jakarta.validation.Constraint;
import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;
import jakarta.validation.Payload;
import java.lang.annotation.*;
import java.time.LocalDate;
import java.time.Period;

@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Constraint(validatedBy = MinimumAgeValidator.class)
public @interface MinimumAge {
    int value() default 18;
    String message() default "Customer must be at least {value} years old";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

public class MinimumAgeValidator implements ConstraintValidator<MinimumAge, LocalDate> {
    private int minimumAge;

    @Override
    public void initialize(MinimumAge constraintAnnotation) {
        this.minimumAge = constraintAnnotation.value();
    }

    @Override
    public boolean isValid(LocalDate dob, ConstraintValidatorContext context) {
        if (dob == null) return true; // @NotNull handles nullability independently
        return Period.between(dob, LocalDate.now()).getYears() >= minimumAge;
    }
}
src/main/java/.../transaction/dto/request/TransferRequest.java (Cross-Field Bean Validation) MODIFIED 
package org.example.enterprisedigitalbankingsystem.transaction.dto.request;

import jakarta.validation.constraints.*;
import lombok.*;
import java.math.BigDecimal;

@Data @NoArgsConstructor @AllArgsConstructor @Builder
public class TransferRequest {

    @NotNull(message = "Source account id is required")
    @Positive(message = "Source account id must be positive")
    private Long sourceAccountId;

    @Positive(message = "Destination account id must be positive")
    private Long destinationAccountId;

    @Positive(message = "Beneficiary id must be positive")
    private Long beneficiaryId;

    @NotNull(message = "Amount is required")
    @DecimalMin(value = "1.00", message = "Amount must be at least 1.00")
    @DecimalMax(value = "10000000.00", message = "Single transfer limit is 10,000,000.00")
    @Digits(integer = 16, fraction = 2, message = "Amount can have at most 2 decimal places")
    private BigDecimal amount;

    @Size(max = 255, message = "Remarks cannot exceed 255 characters")
    private String remarks;

    @AssertTrue(message = "Provide exactly one of destinationAccountId or beneficiaryId")
    public boolean isTargetExclusive() {
        return (destinationAccountId != null) ^ (beneficiaryId != null);
    }

    @AssertTrue(message = "Source and destination account cannot be the same")
    public boolean isNotSelfTransfer() {
        if (sourceAccountId == null || destinationAccountId == null) return true;
        return !sourceAccountId.equals(destinationAccountId);
    }
}
Bean Validation Best Practice (Null Handling): Notice how MinimumAgeValidator and isNotSelfTransfer() return true when a field is null. That is standard Jakarta Validation convention so @NotNull reports missing fields without duplicate misleading messages!
