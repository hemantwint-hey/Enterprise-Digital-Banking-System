1. Core Concepts: Why "Free" Spring Data Sorting Has Hidden Production Bugs

Once controllers accept Pageable (Day 77), Spring Web automatically binds query parameters like ?sort=amount,desc&sort=createdAt,asc into a Sort object. However, passing raw client Sort objects straight into JPA repositories introduces four classic enterprise hazards:

Client Request: ?page=0&size=20&sort=amount,desc │ ▼ SortValidator.validateAndApply(pageable, ALLOWED_TX_FIELDS, defaultSort) ├─► Check 1: Is every Sort.Order property in ALLOWED_TX_FIELDS? │ └─ NO (e.g. ?sort=sourceAccount.customer.user.password) ──► 400 BadRequestException! ├─► Check 2: Did client omit ?sort? ──► Apply Domain Default (createdAt DESC) └─► Check 3: Is unique column "id" in Sort? └─ NO ──► Append deterministic tie-breaker (.and(Sort.by(DESC, "id"))) ▼ Clean SQL: ORDER BY amount DESC, id DESC LIMIT 20 OFFSET 0
Production Hazard What Happens Without Day 78 Guardrails Day 78 Architectural Solution
1. Relation Traversal / Info Leak ?sort=customer.user.password causes Hibernate to auto-JOIN customers and users and leak sort ordering of sensitive columns. Strict per-entity Set<String> ALLOWED_SORT_FIELDS whitelist checked inside SortValidator before any SQL runs.
2. 500 on Unknown Property ?sort=invalidCol,asc throws PropertyReferenceException, hitting our 500 catch-all in GlobalExceptionHandler. Intercept in SortValidator + add global handler for org.springframework.data.core.PropertyReferenceException (400).
3. Rigid Repository OrderBy Our existing repo methods end in ...OrderByCreatedAtDesc! Spring prepends that hardcoded column BEFORE dynamic Pageable sorts, breaking ?sort=amount,asc! Remove rigid OrderBy... suffixes from repository method names; pass dynamic Sort inside Pageable via @PageableDefault & SortValidator.
4. Shifting Rows Across Pages Sorting solely by createdAt when 2 rows share the exact timestamp yields unstable MySQL row order across page 0 → page 1. Automatically append deterministic primary-key tie-breaker (id) when id is not already in the sort orders.

3. Planned Code: Centralized SortValidator & Global Exception Guard

src/main/java/.../common/util/SortValidator.java NEW 
package org.example.enterprisedigitalbankingsystem.common.util;

import org.example.enterprisedigitalbankingsystem.exception.BadRequestException;
import org.springframework.data.domain.PageRequest;
import org.springframework.data.domain.Pageable;
import org.springframework.data.domain.Sort;
import java.util.Set;

public final class SortValidator {

    private SortValidator() {}

    /**
     * Validates all requested sort fields against a strict per-entity allowlist,
     * applies domain defaults when unsorted, and appends primary-key tie-breaker ("id").
     */
    public static Pageable validate(Pageable pageable, Set<String> allowedFields, Sort defaultSort) {
        if (pageable == null || pageable.isUnpaged()) {
            return PageRequest.of(0, 20, ensureDeterministicIdSort(defaultSort));
        }

        Sort requestedSort = pageable.getSort();
        if (requestedSort.isUnsorted()) {
            return PageRequest.of(
                    pageable.getPageNumber(),
                    pageable.getPageSize(),
                    ensureDeterministicIdSort(defaultSort));
        }

        for (Sort.Order order : requestedSort) {
            String property = order.getProperty();
            if (!allowedFields.contains(property)) {
                throw new BadRequestException(
                        "Invalid sort field '" + property + "'. Allowed fields: " + allowedFields);
            }
        }

        return PageRequest.of(
                pageable.getPageNumber(),
                pageable.getPageSize(),
                ensureDeterministicIdSort(requestedSort));
    }

    private static Sort ensureDeterministicIdSort(Sort sort) {
        if (sort.getOrderFor("id") != null) {
            return sort;
        }
        Sort.Direction tieDirection = sort.stream()
                .findFirst()
                .map(Sort.Order::getDirection)
                .orElse(Sort.Direction.DESC);
        return sort.and(Sort.by(tieDirection, "id"));
    }
}

TransactionServiceImpl.java (Using SortValidator + Default Sort) MODIFIED 
private static final Set<String> ALLOWED_TX_SORT_FIELDS = Set.of(
        "id", "createdAt", "amount", "transactionType", "transactionStatus", "transactionReference"
);
private static final Sort DEFAULT_TX_SORT = Sort.by(Sort.Direction.DESC, "createdAt");

@Override
@Transactional(readOnly = true)
public PagedResponse<TransactionSummaryResponse> getTransactionHistory(Long accountId, Pageable pageable) {
    if (!accountRepository.existsById(accountId)) {
        throw new ResourceNotFoundException("Account not found with id: " + accountId);
    }

    Pageable validated = SortValidator.validate(pageable, ALLOWED_TX_SORT_FIELDS, DEFAULT_TX_SORT);

    Page<TransactionSummaryResponse> page = transactionRepository
            .findBySourceAccountIdOrDestinationAccountId(accountId, accountId, validated)
            .map(transactionMapper::toSummaryResponse);

    return PagedResponse.from(page);
}

5. Planned Code: Multi-Column Sort Support & Cache Key Safety

AccountServiceImpl.java (Validated Sort Inside @Cacheable Key) MODIFIED 
private static final Set<String> ALLOWED_ACCOUNT_SORT_FIELDS = Set.of(
        "id", "accountNumber", "balance", "accountType", "accountStatus", "branch", "createdAt"
);
private static final Sort DEFAULT_ACCOUNT_SORT = Sort.by(Sort.Direction.DESC, "createdAt");

// Notice: SortValidator runs inside service; invalid sort throws 400 BEFORE caching junk keys!
@Override
@Transactional(readOnly = true)
@Cacheable(value = "accountsByCustomer",
           key = "#customerId + ':' + #pageable.pageNumber + ':' + #pageable.pageSize + ':' + #pageable.sort.toString()")
public PagedResponse<AccountSummaryResponse> getAccountsByCustomerId(Long customerId, Pageable pageable) {
    if (!customerRepository.existsById(customerId)) {
        throw new ResourceNotFoundException("Customer not found with id: " + customerId);
    }
    Pageable validated = SortValidator.validate(pageable, ALLOWED_ACCOUNT_SORT_FIELDS, DEFAULT_ACCOUNT_SORT);
    return PagedResponse.from(accountRepository.findByCustomerId(customerId, validated)
            .map(accountMapper::toSummaryResponse));
}
